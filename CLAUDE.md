# Мои пары — инструкции для Claude Code

PWA-расписание преподавателя КубГУ (факультет РГФ): неделя пар, тап — подсказка, удержание — перенос,
отмена с размытием, аудитории, ссылка в Google Календарь. Устанавливается на Android с GitHub Pages,
работает без интернета. Сейчас пользователь один; позже — коллеги факультета (v2).

Почему так, а не иначе: `docs/decisions.md`. Что дальше и когда менять стек: `docs/roadmap.md`.
Импорт PDF факультета (следующая версия): `docs/pdf-parser.md`.

## Стек — ступень 1. Не менять без явного «да» пользователя

- Чистые HTML, CSS, JavaScript. ES-модули браузера, **без сборки, без npm-зависимостей приложения, без фреймворков**.
- Не предлагать мимоходом React, Vite, TypeScript, Tailwind, библиотеки дат и т. п. Переход — только по
  ступеням и сигналам из `docs/roadmap.md`, одна ступень за раз, и после согласия пользователя.
- Релиз с переходом на новую ступень не добавляет функций. Функции и рефакторинг — в разных релизах.
- `package.json` нужен, чтобы Node понимал ES-модули в тестах. Зависимостей приложения нет и не будет
  до ступени 2. Единственная devDependency — `prettier` (только форматирование, в приложение не попадает).

## Команды

- Тесты модели: `npm test` (Node 22+). Должны проходить перед каждым коммитом.
- Форматирование: `npm run format` (Prettier, конфиг в `.prettierrc`). Запускать перед каждым коммитом.
- Локальный запуск: `python3 -m http.server 8000` → `http://localhost:8000`
  (двойной щелчок по `index.html` не работает: модулям нужен сервер).
- Выкладка: push в `main` → GitHub Pages публикует корень репозитория сам.

## Архитектура

**Стандарт кода — `docs/architecture.md`: читать перед любым изменением кода.** Слои, имена, числа,
функции и проверка `npm run check` — там. Коротко: решения — в `domain/`, рисование — в `ui/views/`.

Путь данных: **касание → `dispatch(action)` → `reduce()` → новое состояние → сохранение → `render()`**.

- `js/domain/` — предметная область, чистые функции. **Никогда не трогает `document`, `window`, `localStorage`.**
  Все изменения данных — только новые `case` в `reduce()` (`domain/changes.js`); `reduce` возвращает новое состояние (`structuredClone`).
- `js/store/store.js` — единственная переменная `state`, `dispatch`, `subscribe`, сохранение в `localStorage` (ключ `pary`).
  Настройки интерфейса — `js/store/prefs.js` (ключ `pary.prefs`).
- `js/ui/*` — читает состояние, рисует строками HTML, превращает касания в действия. Модель о UI не знает.
- Правила «что можно с парой и что можно поставить в клетку» — только `can()` и `canPlace()` в `domain/rules.js`.
  Интерфейс их спрашивает и показывает `reason`, сам ничего не решает (план и факт — `docs/decisions.md`).
  Показать ли кнопку — `isApplicable(operation, lessonState(…))`; можно ли нажать прямо сейчас — `can({…})`.
- `js/config/` — настройки: `university.js` (звонки, курсы, палитра, предметы, семестр, праздники),
  `interface.js` (времена и отступы), `app.js` (версия, ключи хранилища, схема). Слова языка — `js/lang/ru.js`.
- Действия — простые объекты (`{ type: ACTION.EDIT, lesson, changes, scope }`): в v2 они станут очередью синхронизации.

Модель расписания (как в iCalendar):

- **Rule** — повторяющаяся пара «каждую среду, 5-я пара» с `from`/`until`.
- **RuleException** — правка одной даты правила, ключ `ruleId|YYYY-MM-DD` (`ruleExceptionKey`): `cancelled`,
  `deleted`, `moveTo`, `patch`. В данных лежат в `exceptions` — имя ключа не меняется.
- **OneOff** — разовая пара.
- **Lesson** — вычисленное занятие недели (`weekLessons`), в данных не хранится. `lesson.ruleDate` — дата по правилу до переноса.
- `SCOPE.THIS_DATE` пишет исключение; `SCOPE.FUTURE` меняет правило с этой даты или делит его на «до» и «после»
  (`editLesson` в `domain/changes.js`). Значения `SCOPE` и `PLACE_KIND` в данных не хранятся.

## Обязательные правила при изменениях

1. **Форма данных изменилась** → поднять `SCHEMA` в `config/app.js`, добавить шаг в `migrate()`, тест миграции.
   Данные пользователя в телефоне терять нельзя.
2. **Добавлен или переименован файл** → обновить список `FILES` в `sw.js` и поменять имя кэша
   (`pary-v0.3` → `pary-v0.4`), иначе офлайн сломается.
3. **Новый релиз** → `APP_VERSION` в `config/app.js`, `version` в `package.json`, имя кэша в `sw.js`.
4. **Изменение модели** → тест в `tests/domain/` — файл с тем же именем, что у файла кода (чистые функции проверяются без браузера).
5. Пользовательский текст в HTML — только через `esc()`.
6. Новые id — `crypto.randomUUID()`. Даты — строки `YYYY-MM-DD`, функции из `js/domain/dates.js`.
7. Касания: удержание 280 мс до переноса, сдвиг больше 10 px раньше — это прокрутка. Не ломать:
   проверено на Samsung Galaxy A54; изменения в `gestures.js` пользователь проверяет на телефоне.

## Интерфейс

- Весь текст интерфейса — на русском, по-человечески, без канцелярита и восклицаний. Кнопка говорит, что
  произойдёт («Перенести», «Сохранить»), уведомление повторяет то же слово.
- Цвета — только через CSS-переменные из `css/app.css` (светлая и тёмная тема). Цвет курса — классы `course-1…course-4`.
- Зоны касания не меньше 44 px. Никаких эмодзи. Иконки — инлайн SVG.
- Утверждённый макет — вариант А (сетка недели) + подсказка по тапу. Новые экраны сначала согласуются в макете.

## Приватность

Репозиторий публичный. Не писать в код, тесты и коммиты имена, фамилии, данные студентов.
Поле `teacher: ''` означает «я». Личное — только в `CLAUDE.local.md` (он в `.gitignore`).
PDF расписания факультета (там имена преподавателей) лежат в `samples/` — папка в `.gitignore`, не коммитить.
Фамилию для поиска своих пар при импорте пользователь вводит в приложении, в коде её нет.

## Как работать с пользователем

- Он бывший фронтенд-разработчик, возвращает форму и **хочет понимать каждую строку**. Код — читаемый,
  с короткими комментариями на русском, без хитростей ради краткости. После изменений — объяснить, что и почему.
- Просит спланировать — сначала план и согласие, потом код. Не начинать реализацию, пока он не сказал «да».
- Перед сборкой функции на внешних данных (например, импорт PDF) — запросить свежие исходники и ждать.
- Маленькие коммиты, сообщения на русском в повелительном наклонении: «Добавить импорт PDF: разбор сетки».
- Перед push — `npm test`. Push — только когда пользователь попросил или согласовал релиз.
