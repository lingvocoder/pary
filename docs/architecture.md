# Архитектура и стандарт кода

Этот файл — закон для каждого изменения. Код, который ему не соответствует, не коммитится. Нашёл старый код, который нарушает стандарт, — чинить отдельным коммитом, а не мимоходом.

## Главная идея: решения отдельно от рисования

Приложение устроено как ресторан.

- **Предметная область** — книга рецептов. В ней написано, что можно приготовить и как, но нет ни плиты, ни посетителей.
- **Хранилище** — склад: всё, что есть, лежит в одном месте и выдаётся по накладной (`dispatch`).
- **Представления** — подача: берут готовое блюдо и красиво кладут на тарелку, сами ничего не готовят.
- **Обработчики** — официант: принял заказ, спросил кухню, отнёс на стол. Ни рецептов, ни сервировки он не придумывает.

Отсюда правило, которое проверяется первым: **каждая функция делает одно из четырёх — решает, хранит, рисует или связывает.** Две вещи сразу нельзя.

## Слои и папки

```
js/
  main.js                 запуск: связывает слои, больше ничего
  config/
    app.js                версия, ключи хранилища, номер схемы
    university.js         всё про вуз: звонки, курсы, предметы, семестр, праздники, палитра
    interface.js          времена и размеры интерфейса: удержание, тост, отступы
  lang/
    ru.js                 слова языка: дни, месяцы, склонение (plural)
  domain/                 предметная область — ЧИСТЫЕ функции
    dates.js              даты-строки 'YYYY-MM-DD'
    lessons.js            занятия недели, кто в слоте, следующая пара, фаза, праздник
    rules.js              что можно с занятием и что можно поставить в клетку
    changes.js            reduce() и все изменения данных
    hours.js              подсчёт часов
    forms.js              черновик новой пары, проверка формы, что изменилось
    texts.js              все составные тексты: «через 1 ч 10 мин», тосты, флаги
    calendar-link.js      ссылка в Google Календарь
    seed.js, migrate.js   исходные данные и миграции
  store/
    store.js              state, dispatch, subscribe, сохранение
    prefs.js              настройки интерфейса
  ui/
    views/                представления — ЧИСТЫЕ функции «данные → HTML-строка»
    geometry.js           чистые расчёты положения (где поставить подсказку)
    screen-state.js       что сейчас на экране: открытая неделя, её занятия
    dom.js                $, esc
    toast.js, layers.js, icons.js
    week-screen.js, popover.js, editor.js, menu.js, hours.js, sheets.js, gestures.js   обработчики
tests/                    по файлу на каждый файл domain/, плюс geometry, texts
```

### Кто кого может импортировать

```
config, lang  ←  domain  ←  store  ←  ui
                    ↑                   │
                    └── views ──────────┘  (views: только config, lang, domain, icons, dom.esc)
```

- `config/`, `lang/` не импортируют ничего из проекта.
- `domain/` импортирует только `config/`, `lang/` и сам себя. Никаких `document`, `window`, `localStorage`, `getState()` внутри. Не читать текущее время: `new Date()` без аргументов и `Date.now()` запрещены, текущее время — параметр `now`.
- `store/` импортирует `domain/` и `config/`.
- `ui/views/` — чистые функции: получают данные, возвращают HTML-строку. Не вызывают `getState`, `dispatch`, `can`, `document`, `new Date()`. Всё, что нужно решить («показывать ли кнопку календаря»), приходит готовым полем.
- Остальные файлы `ui/` — обработчики: читают экран и время, спрашивают `domain/`, вызывают `dispatch`, вставляют HTML из `views/`. Правил и текстов не сочиняют.

Нарушил направление — значит, функция лежит не в своём слое.

## Имена

- **Никаких однобуквенных и обрезанных имён.** Исключение одно: `i` и `j` — счётчики в коротком цикле `for`. `$` — общепринятое имя для поиска элемента, живёт в `dom.js`.
- Имя говорит, **что это**, а не какого оно типа: `lesson`, `rule`, `weekStartDate`, `occupant`, `newSlot`. Не `o`, `r`, `ws`, `b`, `ns`, `data`, `obj`, `tmp`.
- Логические значения — вопросом: `isHoliday`, `hasRoom`, `canMove`, `wasChanged`.
- Функции — глаголом: `findLessonAt`, `formatHeroWhen`. Чистые функции текста — `format…`. Представления — только `…View`: `cardView`, `popoverView`. `render…` — функции, которые вставляют HTML в страницу.
- Константы — `UPPER_SNAKE_CASE`, единицы в имени: `TOAST_DURATION_MS`, `SCREEN_EDGE_PX`.
- Обработчики событий: параметр — `event`, не `e`.
- Одно понятие — одно слово во всём коде:

| Понятие                       | В коде                               | Не так                           |
| ----------------------------- | ------------------------------------ | -------------------------------- |
| занятие в сетке (вычисляется) | `lesson`, тип `Lesson`               | `o`, `occ`, `occurrence`, `pair` |
| повторяющаяся пара            | `rule`, тип `Rule`                   | `r`, `tpl`                       |
| правка одной даты правила     | `ruleException`, тип `RuleException` | `e`, `ex`                        |
| разовая пара                  | `oneOff`, тип `OneOff`               | `once`, `one`                    |
| номер пары 1…9                | `slot`                               | `n`, `s`, `si`                   |
| дата по правилу до переноса   | `ruleDate`                           | `orig`                           |
| состояние данных              | `state`                              | `s`                              |
| состояние экрана              | `screenState`                        | `ui`                             |

- В разметке — тоже смысл: `id="editor-group"`, `data-action="export"`, `data-course="3"`, `data-scope="future"`. Не `id="eg"`, не `data-a`.
- Ключи, которые лежат в сохранённых данных (`rules`, `exceptions`, `oneOffs`, `moveTo`, `cancelled` и т. д.), **не переименовываются**: это схема данных в телефоне, её меняют только через `SCHEMA` и `migrate()`.

## Числа и списки

- **Любое число, кроме 0, 1 и −1, получает имя.** Настройки вуза и интерфейса — в `config/`. Законы календаря и языка (дней в неделе, номер воскресенья, правила склонения) — константой в своём модуле: `domain/dates.js`, `lang/ru.js`. Списки (`[1, 2, 3, 4]`) — тоже.
- Число, связанное с CSS (длительность анимации), — константа с комментарием, где в `app.css` его пара.
- Текст, в котором есть число из настроек («В ближайшие 4 недели»), строится из той же константы.
- Строки, которые служат ключами («`__other__`», `'future'`), — константы с понятным значением.

## Функции

- Одна функция — одна работа, и её можно назвать без «и». `openPopover` открывает подсказку; что в ней написать, решают `texts.js` и `rules.js`, как её нарисовать — `views/popover.js`, куда поставить — `geometry.js`.
- Длиннее 40 строк — повод разбить. Шаблон HTML длиннее 15 строк — собирать из маленьких представлений.
- Больше трёх параметров — объект с именованными полями: `canPlace({ kind, date, slot, now, state, holidays, exceptLessonId })`.
- Повтор кода дважды — вынести в функцию.
- Не больше одного уровня тернарного оператора. Вложенные `? :` — заменить на `if` или таблицу.

## Комментарии

- По-русски, коротко, отвечают на «зачем», а не пересказывают код.
- У каждой экспортируемой функции — JSDoc: что делает, параметры, что возвращает.
- Комментарий в начале файла: какая у него одна тема.

## Тесты

- Каждый модуль `domain/`, `ui/geometry.js`, `lang/ru.js` — с тестами. Тест проверяет поведение, а не каждую функцию по отдельности: мелкие помощники проверяются через функции, которые их используют. Файл теста зеркалит файл кода: `domain/rules.js` → `tests/domain/rules.test.js`.
- Представления не тестируются юнит-тестами: их проверяет сравнение скриншотов и телефон.
