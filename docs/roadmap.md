### 0.3.2 — перезагрузка после обновления

- **Что.** Перезагрузка страницы по `controllerchange`, только если контроллер уже был (обновление,
  а не первая установка), и не больше одного раза.
- **Зачем.** Первый запуск после выкладки обслуживает ещё старый service worker: новый `index.html`
  приходит из сети, а CSS и JS — из старого кэша. При переименовании классов страница открывается
  без части стилей до следующего запуска.
- **Когда заработает.** Обработчик живёт в `main.js`, поэтому начнёт работать с обновления 0.3.2 → 0.3.3.

### 0.3.3 — дизайн-система (Refactoring UI + Tailwind)

- **Источники.**
  - Принципы — `~/.claude/rules/ui-design.md` (книга Refactoring UI).
  - Цвета — палитра Tailwind CSS v4 (https://tailwindcss.com/docs/colors), значения `oklch()`.
  - Иконки — Heroicons (MIT, инлайн-SVG).
  - Образцы компонентов — Tailwind Plus Application UI v4 в `~/Design/tailwind-plus/`.
  - Книгу и Tailwind Plus в репозиторий не копировать.
- **Фреймворк Tailwind не подключаем:** ступень 1, БЭМ, офлайн. Из образцов берём структуру, размеры
  и состояния, утилиты переводим в БЭМ-классы и переменные.
- **Переменные в два слоя.** Шкала с именами как в Tailwind (`--color-gray-500`, `--color-indigo-600`)
  и смысл (`--text`, `--surface`, `--accent`). Компоненты берут только смысловые; тёмная тема
  переназначает смысловые на другие ступени.
- **Цвета в макете.** Серые — gray, основной — indigo, курсы 1–4 — sky, emerald, amber, fuchsia
  (ещё подтверждается). Палитра «важных» пар в `config.js` переходит на ступени Tailwind.
- **Отменённая карточка.** Убрать `color-mix()` из `.card--cancelled` (штриховка и цвет левой полосы),
  заменить ступенями палитры.
- **Шаги.**
  1. Аудит — готов.
  2. Макет «сейчас → после» на холсте «Мои пары — макет» в claude.ai — светлая тема готова,
     тёмная в работе.
  3. Перенос в код — после «да» пользователя по макету.
- **Ограничение.** Полировка, а не переделка; функции не добавлять.
- **Единственная новая логика в 0.3.3:** подсказка внизу экрана показывается только до первого тапа
  и первого удержания — один раз и навсегда. Флаг хранится отдельным ключом `localStorage` `'pary.prefs'`
  через новые функции `getPref`/`setPref` в `store.js`, вне `State`: `SCHEMA` и `migrate()` не меняются,
  в резервную копию флаг не попадает.

## Ступени перехода на «взрослый» стек

Переходим по сигналу, а не по календарю. Одна ступень за раз. Релиз с переходом не добавляет функций.

| Ступень       | Сигнал                                                                         | Что меняется                                                                   |
| ------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 0             | —                                                                              | Один файл, чистые HTML/CSS/JS (версии 0.1–0.2)                                 |
| 1 ← сейчас    | Второй экран или файл длиннее ~1000 строк                                      | ES-модули браузера, без сборки                                                 |
| 2. Vite       | Нужна npm-библиотека, SCSS или живое обновление на телефоне                    | Тот же код через Vite; выкладка через GitHub Actions по `git push`             |
| 3. TypeScript | Модель готовится к серверу или баг из-за неверной формы данных                 | Сначала только `js/model.js` (JSDoc-типы уже есть)                             |
| 4. React      | Старт v2: вход, данные с сервера, экранов ≥ 4, ручная перерисовка теряет фокус | Экраны по одному в компоненты; `reduce` → `useReducer` как есть                |
| 5. Сервер     | Пройден критерий v2                                                            | Supabase, вход, синхронизация, разбор PDF на сервере для всего факультета      |
| 6. Масштаб    | Попросил другой факультет или вуз                                              | Своя сетка звонков, роли, push-уведомления, при необходимости нативная обёртка |

## Задел для масштабирования (уже в коде)

1. Модель не трогает страницу — переезжает в TypeScript и React без изменений.
2. Все изменения через `dispatch(action)` — в React это `useReducer`, для сервера — очередь синхронизации.
3. Версия схемы данных + `migrate()` — данные переедут с телефона на сервер без потерь.
4. Уникальные id (UUID) — у разных преподавателей ничего не столкнётся.
5. Поля `teacher`, `source`, `importKey` — для импорта и v2.
6. Сетка звонков в `config.js`, а не в коде.
7. JSDoc-типы в модели — переход на TypeScript сводится к переименованию.
8. Разбор PDF — за одной функцией `parsePdf(file)` (появится в 0.4): при переезде на сервер меняется только она.
